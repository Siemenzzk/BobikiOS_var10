## Сборка и запуск

Собирается через простой Makefile, поэтому надо gcc.
Я ставил себе на винду MinGW для этого, но вам на линуксе это не надо 

По самой работе с Makefile ниче необычного нет, но на всякий случай:
 
**Сборка:**
```bash
mingw32-make        # Windows
make                # Linux
```
 
**Запуск:**
```bash
./rtos.exe          # Windows
./rtos.out          # Linux
```
 
**Очистка (если вдруг у вас make не видит изменений и не пересобирает `rtos.exe`):**
```bash
mingw32-make clean  # Windows
make clean          # Linux
```

## Ядро ОС — че я уже сделал,чтобы вам попроще было разгребать это
 
### TCB (Task Control Block)
 
Каждая задача в системе представлена структурой `TCB` в `rtos_api.h`. В ней хранится всё что система знает о задаче:
 
- `id` — индекс задачи в глобальной таблице `task_table`
- `priority` — статический приоритет, задаётся при объявлении через макрос `TASK`
- `state` — текущее состояние: `SUSPENDED`, `READY` или `RUNNING`
- `context` — сохранённый контекст выполнения (`jmp_buf`), нужен для возобновления задачи с того же места, где она прервалась
- `func` — указатель на функцию задачи, используется при первом запуске
- `started` — флаг: 0 если задача ещё ни разу не запускалась, 1 если уже запускалась
- `activation_order` — порядковый номер активации, нужен для разрешения конфликтов при одинаковых приоритетах
Все TCB хранятся в глобальном массиве `task_table[MAX_TASKS]` в `global.c`.

### Регистрация задач
 
Задачи объявляются макросами в пользовательском коде (в `test_main.c` есть пример):
 
```c
TASK(task1, 5) { ... }   // объявляет функцию и сохраняет приоритет
DeclareTask(task1);       // объявляет переменную-идентификатор
```
 
Перед запуском ОС каждую задачу нужно зарегистрировать через `register_task()` — она заполняет TCB и добавляет задачу в `task_table`, возвращая её индекс:
 
```c
task1 = register_task(task1_func, task1_priority);
```

### Планировщик — `find_next_task()`
 
Реализован в `task.c`. Проходит по всему `task_table` и ищет задачу с наивысшим приоритетом среди тех, что находятся в состоянии `READY`. При равных приоритетах побеждает задача, которая была активирована раньше, то есть с меньшим `activation_order`.

### Диспетчер — `dispatch()`
 
Реализован в `task.c`. Вызывается каждый раз когда нужно переключить задачу. Работает как-то так:
 
1. Спрашивает планировщик кто следующий
2. Если никого нет — вызывает `ShutdownOS()`
3. Если текущая задача есть — сохраняет её контекст через `setjmp()`. Когда задачу потом возобновят через `longjmp()`, выполнение вернётся именно сюда и функция выйдет через `return`
4. Переключается на следующую задачу: если она запускается впервые — вызывает `func()` напрямую, иначе — восстанавливает контекст через `longjmp()`

### ActivateTask и TerminateTask
 
`ActivateTask()` переводит задачу из `SUSPENDED` в `READY`, присваивает ей `activation_order` и переводит текущую задачу в `READY` (она уступает процессор), после чего вызывает диспетчер.
 
`TerminateTask()` переводит текущую задачу в `SUSPENDED`, сбрасывает её `started` и `activation_order`, обнуляет `current_task` и вызывает диспетчер.

### StartOS и ShutdownOS
 
`StartOS()` в `os.c` принимает стартовую задачу, переводит её в `READY` и запускает диспетчер — с этого момента система работает. `ShutdownOS()` сбрасывает флаг `os_running` и обнуляет `current_task`, после чего управление возвращается в `main()`.
