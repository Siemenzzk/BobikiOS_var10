## Сборка и запуск

Собирается через простой Makefile, поэтому надо gcc.
Я ставил себе на винду MinGW для этого, но вам на линуксе это не надо 

По самой работе с Makefile ниче необычного нет, но на всякий случай:
 
**Сборка:**
```bash
mingw32-make        # Windows
make                # Linux
```
 
**Запуск:**
```bash
./rtos.exe          # Windows
./rtos.out          # Linux
```
 
**Очистка (если вдруг у вас make не видит изменений и не пересобирает `rtos.exe`):**
```bash
mingw32-make clean  # Windows
make clean          # Linux
```

## Ограничения, с которыми я столкнулся и пока не решил

Переключение контекста реализовано через `setjmp`/`longjmp` на едином стеке процесса.
Это означает что если задача возобновляется через `longjmp` внутри глубокой цепочки 
вызовов (например `task_func → SetSysEvent → dispatch`), её стек может быть повреждён 
выполнением другой задачи. В реальных ОСРВ эта проблема решается выделением отдельного 
стека для каждой задачи. Для реализации изолированных стеков задач на чистом C без 
ассемблера не существует переносимого механизма - стандарт языка не предоставляет 
безопасного способа переключения указателя стека. Теоретически проблема решается ассемблерным
фрагментом кода, однако спецификация проекта рекомендует исключить использование ассемблера, 
поэтому мы сознательно оставили текущую одностековую модель, понимая её ограничения.
